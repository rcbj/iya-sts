## What you can contribute

We welcome contributions including:

- Bug fixes and security improvements.
- New authentication, federation, and authorization capabilities.
- Protocol interoperability improvements.
- Performance, scalability, and reliability improvements.
- Tests, test infrastructure, and reproducible test cases.
- Documentation, examples, and developer tooling.
- Improvements to installation, deployment, observability, and operations.

For significant changes, please open an issue or discussion before investing substantial effort. This helps establish the intended behavior and reduces the risk of implementing a change that conflicts with the project's direction.

## Submitting a contribution

1. Review existing issues and discussions to determine whether your proposed change has already been considered.
2. For substantial changes, open an issue describing the problem, proposed solution, and relevant design considerations.
3. Fork the repository and create a branch for your change.
4. Make your changes and add or update tests as appropriate.
5. Run the relevant tests, formatting checks, and build steps.
6. Submit a pull request describing the change, its motivation, and any compatibility or migration implications.
7. Complete the CLA process if you have not already done so.

Pull requests may be reviewed for correctness, maintainability, security, compatibility, test coverage, documentation, and alignment with project objectives.

Submitting a pull request does not guarantee acceptance. The maintainers may request changes or decline a contribution.

## Contribution quality

Please make contributions focused, understandable, and maintainable.

- Follow the conventions and architecture established by the existing codebase.
- Include tests for new functionality and bug fixes where practical.
- Document externally visible behavior and configuration changes.
- Avoid unrelated changes in the same pull request.
- Identify breaking changes and their migration implications.
- Do not include credentials, private keys, tokens, personal information, or other sensitive material in source code, tests, logs, or examples.

## Third-party code and dependencies

Only submit code and other materials that you are legally entitled to contribute.

Identify third-party code, copied snippets, generated material, and dependencies where relevant. Include applicable copyright notices and license information.

Do not submit code copied from another project unless its license and applicable terms permit the intended use and distribution within `iya-sts`.

## Security vulnerabilities

Please do not disclose exploitable security vulnerabilities in public issues or pull requests.

Follow the security reporting instructions in the repository's `SECURITY.md`, if present. If no security reporting process is published, contact the project maintainers privately to arrange responsible disclosure.

Security-related contributions may require additional review before they are merged or publicly disclosed.

## Community expectations

Be respectful and constructive in issues, discussions, reviews, and pull requests.

We expect participants to focus on technical merit, communicate disagreements professionally, and help maintain a productive environment for everyone.

## Questions

If you are unsure whether a proposed contribution is appropriate, whether you have the necessary rights to submit it, or how the CLA applies to your situation, open a discussion or contact the project maintainers before submitting the contribution.

Thank you for helping improve `iya-sts`!
